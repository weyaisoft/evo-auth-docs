Handler mounts for other runtimes ​

This page is for a developer whose app server is also the auth server: Hono, Bun, Deno or plain Node, with a storage adapter of their own. If your auth endpoints run on Convex and your app server only relays to them, you want the proxy instead: see The proxy and the client address. Next is a proxy mount only; it has no handler snippet.

Every block on this page is marked unverified: it type-checks against the documented API (pnpm check:snippets) and nobody has run it. Test your mount before you rely on it.

What a handler mount needs ​

createAuth(config, secrets, { logger?, clock? }) returns { handler }. Build it once, when the server starts:

ts
const auth = createAuth(config, fromEnv(env, "auth"));

config is the object validateConfig returned. fromEnv(env, "auth") reads EVO_AUTH_SECRET, EVO_AUTH_SIGNING_KEY, EVO_AUTH_PUBLIC_KEYS and the credentials of each enabled provider, and refuses to start naming any that are missing or weak. logger receives event names and reason codes only. clock is the time in milliseconds; it must be the clock your storage adapter's transactions read, to within clockSkewSeconds.

Each request is answered with auth.handler(request, { storage, connectionAddress? }):

MemberWhat it is
storageYour storage adapter: an object with the operations of the Storage interface from @evo-auth/core/storage.
connectionAddressThe client's address and where you got it: { source: "connection", address }, with address a literal or null. Read only when EVO_AUTH_PROXY_SECRET is not set.

Without a proxy secret the handler takes the client address only from connectionAddress and reads no header. A runtime that reports no address gets a 503. With the proxy secret set, the handler ignores connectionAddress and accepts only requests that carry the right proxy secret and an address from the proxy, so a direct mount like the ones below must not set the proxy secret.

The source convex_dev_metadata exists for Convex's development mode only and is accepted only when cookies.devMode is on. A bare string instead of the { source, address } object is refused with a TypeError.

Storage ​

@evo-auth/core/storage holds the Storage interface, the record types and the transaction interface. The only production adapter in this repository is the Convex component's, and it is not exported. An adapter you write yourself must pass the contract suite: runStorageContract from @evo-auth/core/testing, which also provides an in-memory adapter for tests. The in-memory adapter is for tests, not for production.

In each block below, auth and storage are declared, not built. Replace those two lines with imports from your own code.

Hono ​

One route on the path of publicUrl hands every request to the handler. getConnInfo(c).remote.address is the connection address. The one import confirmed here is @hono/node-server/conninfo, which is the Node adapter. On another runtime, import getConnInfo from that runtime's adapter; Hono's conninfo helper page lists them. No other path is printed here, because a path that was right for one version of Hono may be wrong for yours. remote.address is optional in Hono's type, so the snippet passes it as it is and the handler's 503 covers a missing value.

ts
import { Hono } from "hono";
import { getConnInfo } from "@hono/node-server/conninfo";
import type { Auth } from "@evo-auth/core";
import type { Storage } from "@evo-auth/core/storage";

// Replace these two lines with imports from your own code: `auth` is what createAuth returned and `storage` is your
// storage adapter.
declare const auth: Auth;
declare const storage: Storage;

const app = new Hono();

app.all("/auth/*", (context) =>
  auth.handler(context.req.raw, {
    storage,
    connectionAddress: { source: "connection", address: getConnInfo(context).remote.address ?? null },
  }),
);

export default app;

Bun ​

Bun.serve passes the request and the server; server.requestIP(request) states the connection address.

ts
import type { Auth } from "@evo-auth/core";
import type { Storage } from "@evo-auth/core/storage";

// Replace these two lines with imports from your own code: `auth` is what createAuth returned and `storage` is your
// storage adapter.
declare const auth: Auth;
declare const storage: Storage;

Bun.serve({
  fetch(request, server) {
    if (!new URL(request.url).pathname.startsWith("/auth/")) return new Response("Not found", { status: 404 });
    const connection = server.requestIP(request);
    return auth.handler(request, { storage, connectionAddress: { source: "connection", address: connection?.address ?? null } });
  },
});

Deno ​

Deno.serve passes the request and the connection information.

ts
import type { Auth } from "@evo-auth/core";
import type { Storage } from "@evo-auth/core/storage";

// Replace these two lines with imports from your own code: `auth` is what createAuth returned and `storage` is your
// storage adapter.
declare const auth: Auth;
declare const storage: Storage;

Deno.serve((request, info) => {
  if (!new URL(request.url).pathname.startsWith("/auth/")) return new Response("Not found", { status: 404 });
  return auth.handler(request, { storage, connectionAddress: { source: "connection", address: info.remoteAddr.hostname } });
});

Node ​

Node's HTTP server needs a small adapter: it builds a Request from the incoming message and writes the Response back, with every Set-Cookie header kept as its own line.

ts
import { createServer, type IncomingMessage, type ServerResponse } from "node:http";
import { Readable } from "node:stream";
import type { Auth } from "@evo-auth/core";
import type { Storage } from "@evo-auth/core/storage";

// Replace these two lines with imports from your own code: `auth` is what createAuth returned and `storage` is your
// storage adapter.
declare const auth: Auth;
declare const storage: Storage;

async function serve(incoming: IncomingMessage, outgoing: ServerResponse): Promise<void> {
  const url = new URL(incoming.url ?? "/", `http://${incoming.headers.host ?? "localhost"}`);
  if (!url.pathname.startsWith("/auth/")) {
    outgoing.writeHead(404).end();
    return;
  }
  const headers = new Headers();
  for (const [name, value] of Object.entries(incoming.headers)) {
    if (Array.isArray(value)) for (const item of value) headers.append(name, item);
    else if (value !== undefined) headers.set(name, value);
  }
  const hasBody = incoming.method !== "GET" && incoming.method !== "HEAD";
  const request = new Request(url, {
    method: incoming.method,
    headers,
    ...(hasBody ? { body: Readable.toWeb(incoming) as ReadableStream<Uint8Array>, duplex: "half" } : {}),
  });
  const response = await auth.handler(request, {
    storage,
    connectionAddress: { source: "connection", address: incoming.socket.remoteAddress ?? null },
  });
  const answer: Record<string, string | string[]> = {};
  response.headers.forEach((value, name) => {
    if (name !== "set-cookie") answer[name] = value;
  });
  answer["set-cookie"] = response.headers.getSetCookie();
  outgoing.writeHead(response.status, answer).end(new Uint8Array(await response.arrayBuffer()));
}

createServer((incoming, outgoing) => {
  serve(incoming, outgoing).catch(() => {
    outgoing.writeHead(500).end();
  });
}).listen(3000);

Behind a platform load balancer the socket address is the balancer's, so every user would share one per-address limit; see the proxy page for what that means and what to do.

The path ​

The auth endpoints answer only under basePath (default /auth) and only on the path exactly as the URL parser writes it: no trailing slash, no doubled slash, no percent-encoded segment and no other letter case. Anything else is a 404. Mount the handler on {basePath}/* and keep your own routes off that path.
