Troubleshooting ​

This page is for whoever is looking at a failed sign-in, a log line or a browser console message. Find the symptom, read what it means and do the fix. Every error code is listed on the error reference. Run pnpm exec evo-auth check (with npm, npx @evo-auth/core check) first: it names missing and weak settings without printing a value.

Start-up and environment ​

SymptomWhat it meansFix
Every auth route answers 503 unavailable on Convex, and the log repeats [evo-auth] register_routes.setup_failed <NAMES>.A variable is missing or refused, or EVO_AUTH_PROXY_SECRET is unset outside the development cookie mode. The line repeats on every refused request until the environment is fixed. Your app's other routes still serve.Set the named variables, push if you changed code, then run evo-auth check. A changed variable applies from the next request, with no push.
npx convex dev fails on the first push, naming EVO_AUTH_PUBLIC_KEYS.auth.config.ts reads it when it loads, and the deployment did not exist yet when you could set it.Set EVO_AUTH_PUBLIC_KEYS on the deployment, then push again.
The app server answers every request with Start's generic 500, with no Cache-Control or Vary.A required variable is missing on the app server. The module that builds the proxy fails before the middleware runs.Read the server log: it names the variable and never its value. Set it and restart.
evo-auth init or keys generate refuses.Git does not confirm the env file is ignored, the file is a link, a key is already there, or evo-auth.config.ts already exists.Read the message: it names the file and the rule. Add the file to .gitignore. Use keys rotate instead of keys generate to change keys.
evo-auth check exits 1 with the JWKS at … could not be reached.check compares your keys with the JWKS your app publishes at {publicUrl}/.well-known/jwks.json, and nothing answers there: the app is not running, or publicUrl points at the wrong address.Start the app and run check again. The other sections of the report are still valid.
fromEnv refuses a variable that is set but empty.An empty value counts as an error.Remove the line, or give it a value. In .env.example the optional variables are commented out for this reason.

Answers from the auth endpoints ​

CodeStatusLikely causeFix
proxy_refused403The two sides hold different EVO_AUTH_PROXY_SECRET values, a request skipped the proxy, or clientAddress returned something that is not one IP literal. The proxy logs proxy.client_address_refused.Set the same secret on both sides. Check clientAddress: the proxy page.
origin_refused403A POST carried a missing, null or unlisted Origin.Add the page's exact origin to allowedOrigins.
rate_limited429A bucket is full. Retry-After says for how long.Wait. If real users hit it, check that clientAddress gives each user their own address: behind a load balancer the socket address is the balancer's.
oauth_failed400The sign-in cookie was missing, expired or altered, the state did not match, or the provider refused.Start again. Check the callback URL and credentials on GitHub's side.
refresh_reuse401An old refresh token was used again. The session was revoked.The user signs in again. If it happens without theft, look for a client that retries a refresh after the grace window, or a database restore.
signing_failed503The active signing key is missing from the public set.Run evo-auth check and fix the keys.
reverification_required403The action needs a recent confirmation with the provider.The user confirms with the provider, then repeats the action. The components do this.
method_not_allowed405The method is not answered there. OPTIONS always is: there is no CORS. Allow lists what is.Use a listed method.
not_found404The path is not an auth path as written: wrong case, a trailing or doubled slash, an encoded segment, or a query on a route that takes none.Use the exact paths in Configuration. Start answers /AUTH/... with a 404 from the proxy and //auth/... with its own 308.

Signed out when you did not expect it ​

  • Everyone signed out at once: EVO_AUTH_SECRET was replaced, or basePath was changed to a path nested under the old one (once each). See Rotating secrets.
  • A page shows signed out, with new tokens seen as unknown_kid: the server's public key set lacks the active key's id. getAuth sends the handshake, and the loop guard ends it signed out. Set the new EVO_AUTH_PUBLIC_KEYS on that server and run evo-auth check.
  • One session signed out after a restore: a restore from backup signs users out.

Browser console lines that are expected ​

These are normal and need no fix:

  • A 401 on /auth/token after "Sign out everywhere" or after deleting the account. The session is gone, so the refresh is refused, and the provider signs the tab out.
  • A 403 reverification_required before an account delete. The user has not confirmed with the provider recently enough; the dialog then sends them to the provider.
  • Requests shown as aborted when the page navigates away.

The page and the policy ​

  • Sign-in does nothing, and the console shows a form-action violation. Sign-in was started from a form. With form-action 'self', Chrome blocks the redirect that follows a form submission. Use SignInButton or a link.
  • Avatars are missing. img-src must allow https: or the avatar host.
  • A provider button shows an empty square, and the console shows an img-src violation. The provider logos are data: images: add data: to img-src. It is needed only when a provider has an icon, as github() and google() do.
  • Components have no styling, or a style violation appears. Import @evo-auth/react/styles.css from your own origin, and allow style-src 'self'.
  • A hook sees user.id as undefined. A hook receives the stored document: use user._id. The server API returns user.id.
  • The page keeps showing the previous user after you signed in as someone else in another tab. Reload on useAuth().identityChanged: React guide.
