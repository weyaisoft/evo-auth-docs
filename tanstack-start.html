TanStack Start guide ​

This page is for a developer adding EVO_AUTH to a TanStack Start app that uses Convex. The working reference for everything here is examples/tanstack-convex/. Its files are the snippets on this page, and its tests are what make the TanStack Start recipe verified. Read it beside this page.

You need the Convex side first: Convex guide.

The pieces ​

PieceWhere in the exampleWhat it does
Shared configshared/auth-config.tsOne validateConfig object, imported by Convex and by Start. It reads no environment variable.
Proxy and getAuthsrc/lib/auth.server.tscreateAuthProxy relays /auth/* to Convex. createGetAuth reads a page request's cookies.
Proxy routesrc/routes/auth/$.tsMounts the proxy on /auth/* for every method.
Request middlewaresrc/middleware/auth.ts, src/start.tsFor every request outside /auth: page headers, getAuth, the handshake redirect, the nonce and the policy.
Root routesrc/routes/__root.tsxAuthProvider outside ConvexProviderWithEvoAuth, and the reload on identityChanged.

The .server.ts suffix makes Start refuse to bundle a module into the browser build, so no secret reaches client code.

The proxy and getAuth ​

Both objects are made once, at the top of the module, when the server first loads it. A missing or malformed variable then fails the module itself: the server serves no page and proxies no request. Every request gets Start's generic 500, and the server's log names the variable and never its value.

ts
import { createAuthProxy, createGetAuth, fromEnv, type AuthConfig } from "@evo-auth/core";
import { getRequestIP } from "@tanstack/react-start/server";

// Replace these lines with imports from your own code. `authConfig` is the object validateConfig returned. The example
// holds `serverOrigin` in src/lib/env.server.ts: it reads a variable and refuses it unless it is an origin.
declare const authConfig: AuthConfig;
declare function serverOrigin(name: string): string;
declare const process: { readonly env: Record<string, string | undefined> };

export const authProxy = createAuthProxy(
  authConfig,
  { target: serverOrigin("VITE_CONVEX_SITE_URL"), clientAddress: () => getRequestIP() ?? "" },
  fromEnv(process.env, "proxy"),
);

export const getAuth = createGetAuth(authConfig, fromEnv(process.env, "render"));
  • target and clientAddress are both required. target is the Convex HTTP actions origin (VITE_CONVEX_SITE_URL, which the Convex CLI writes into .env.local). It is never derived from publicUrl.
  • clientAddress is the socket recipe, getRequestIP() from @tanstack/react-start/server, with no options and never { xForwardedFor: true }. Behind a platform load balancer the socket address is the balancer's, so pick your host's recipe. See the proxy page.
  • getAuth is made once with createGetAuth(config, fromEnv(env, "render")). It holds the public keys only: it mints nothing and rotates nothing.
  • Never log headers or cookies on the auth paths.

The proxy route, from src/routes/auth/$.ts:

ts
import { createFileRoute } from "@tanstack/react-router";

import { authProxy } from "../../lib/auth.server.js";

const handle = ({ request }: { request: Request }): Promise<Response> => authProxy(request, undefined);

export const Route = createFileRoute("/auth/$")({
  server: { handlers: { ANY: handle } },
});

ANY is Start's catch-all for every method the route lists no handler for, HEAD included. The mounted proxy takes (request, context); Start's recipe ignores the context, so the route passes undefined. The auth endpoints decide what a method gets (405 with Allow).

Middleware, nonce and the handshake ​

src/middleware/auth.ts runs for every request outside /auth:

  1. It sets PAGE_HEADERS (Cache-Control: private, no-store and Vary: Cookie) first, so every response that follows carries them, the handshake redirect and error pages included.
  2. It calls getAuth(request). When the state is handshake, it answers with the 307 to {basePath}/handshake. The handshake rotates the refresh token, sets the cookies and sends the browser back once, to the same page. The handshake re-encodes the query of the redirect it returns to.
  3. It makes a nonce for this response and sets a Content-Security-Policy that names it. The nonce and the auth state go on in the request context.
ts
import { PAGE_HEADERS } from "@evo-auth/core";
import { redirect } from "@tanstack/react-router";
import { createMiddleware } from "@tanstack/react-start";
import { setResponseHeader } from "@tanstack/react-start/server";

import { authConfig } from "../../shared/auth-config.js";
import { getAuth } from "../lib/auth.server.js";
import { contentSecurityPolicy, createNonce } from "../lib/csp.server.js";

const { basePath } = authConfig;

export const authMiddleware = createMiddleware().server(async ({ next, request, pathname }) => {
  if (pathname === basePath || pathname.startsWith(`${basePath}/`)) return next();

  for (const [name, value] of Object.entries(PAGE_HEADERS)) setResponseHeader(name, value);

  const auth = await getAuth(request);
  if (auth.state === "handshake") throw redirect({ href: auth.location, statusCode: auth.status });

  const nonce = createNonce();
  setResponseHeader("Content-Security-Policy", contentSecurityPolicy(nonce));
  return next({ context: { auth, nonce } });
});

Register it in src/start.ts. Declaring requestMiddleware replaces Start's default list, which holds only its CSRF check for server functions. So add createCsrfMiddleware() again once you declare request middleware; the example lists it first:

ts
import { createCsrfMiddleware, createStart } from "@tanstack/react-start";

import { authMiddleware } from "./middleware/auth.js";

const csrfMiddleware = createCsrfMiddleware({ filter: (ctx) => ctx.handlerType === "serverFn" });

export const startInstance = createStart(() => ({ requestMiddleware: [csrfMiddleware, authMiddleware] }));

The nonce reaches the page through the router: getRouter() passes ssr: { nonce: getGlobalStartContext()?.nonce } to createRouter, and the router stamps it on every inline script it renders.

If the state is signed-in, getAuth has already verified the access token, so the page renders signed in with it. If it is signed-out, the page renders signed out. getAuth never reads, returns or forwards a refresh value.

With organizations.enabled on, the signed-in state also has organization: the active organisation from the token as { id, slug, role, permissions }, with the permissions your config's organizations.roles gives the role, or null when the session has none. hasPermission(auth, "docs:edit") from @evo-auth/core answers from it. The token can be up to one access-token lifetime old, so server code that must not trust that reads storage through the server API (listMembers, getOrganization) instead.

The root route ​

tsx
import { publicConfig } from "@evo-auth/core";
import { AuthProvider, useAuth } from "@evo-auth/react";
import { ConvexProviderWithEvoAuth } from "@evo-auth/react/convex";
import stylesheet from "@evo-auth/react/styles.css?url";

// The loader reads, through a server function, the state the middleware put in the request context
// (src/lib/auth-state.ts throws if the middleware did not run) and the browser's part of the config.
const loadAuthState = createServerFn().handler(({ context }) => ({
  initialState: middlewareAuthState(context),
  publicConfig: publicConfig(authConfig),
}));

// In the root component, with `auth = Route.useLoaderData()`:
<AuthProvider initialState={auth.initialState} publicConfig={auth.publicConfig}>
  <ConvexProviderWithEvoAuth client={convex}>
    <ReloadOnIdentityChange />
    <Header />
    <Outlet />
  </ConvexProviderWithEvoAuth>
</AuthProvider>
  • AuthProvider goes outside ConvexProviderWithEvoAuth, which reads its context for the token.
  • publicConfig(authConfig) runs on the server and gives the browser six fields and nothing else. The loader runs once per page load, and the provider reads these two props only when it mounts.
  • The app imports @evo-auth/react/styles.css from its own origin, as a link in the document head.
  • When another tab signs in as someone else, useAuth().identityChanged turns true. The provider has already signed this tab out but never reloads by itself, so the page still shows the first user's content. Reload it:
tsx
function ReloadOnIdentityChange(): null {
  const { identityChanged } = useAuth();
  useEffect(() => {
    if (identityChanged) window.location.reload();
  }, [identityChanged]);
  return null;
}

The content security policy ​

The example's production policy:

DirectiveValueWhy
default-src'self'Anything not listed comes from the app's own origin only.
script-src'self' 'nonce-…'The app's own scripts and inline scripts that carry this response's nonce.
style-src'self'The app's own stylesheets, @evo-auth/react/styles.css included. No inline style.
img-src'self' https: data:The app's images, avatars, which come from the provider over https, and the providers' button logos, which are data: images; data: is needed only when a provider has an icon.
connect-src'self' plus the Convex origin and its WebSocket originThe /auth proxy and server functions, and the Convex client.
object-src'none'No plugin content.
base-uri'none'No <base> element can move where relative script URLs load from.
form-action'self'A form on these pages can submit only to your own origin.
frame-ancestors'none'No other site can frame the pages, so account actions cannot be clickjacked.

Two details to copy:

  • img-src must allow https: or the avatar host, because avatars come from the provider, and data: when a provider has an icon, because the providers' button logos are data: images (see The icon on the button); an image is never script, so data: here lets nothing run. An app whose providers all show letter tiles may leave data: out. style-src 'self' is enough for the components: they apply their theme variables through the CSSOM, which a strict style-src does not block, and render no style attribute.
  • With form-action 'self', start sign-in from SignInButton or a link and never from a form. Chrome applies the directive to the redirect that follows a form submission, so a form whose answer redirects to the provider's sign-in page would be blocked. Reverification and the account actions are top-level navigations and fetch calls, so no page posts a form.

The example's development server also allows 'unsafe-inline' in style-src, for Vite's dev client. Nothing built has it.

Environment variables ​

WhereVariables
Convex deploymentSee the Convex guide.
App server, at run timeVITE_CONVEX_SITE_URL, EVO_AUTH_PUBLIC_KEYS and EVO_AUTH_PROXY_SECRET.
App buildVITE_CONVEX_URL, fixed into the browser bundle when the app is built.

The example requires the proxy secret on both sides. Without it, a deployment in the development cookie mode takes the client address from the leftmost X-Forwarded-For and answers direct requests, which any client can forge.

EVO_AUTH_STAGED_SIGNING_KEY, which keys rotate writes and keys activate moves, appears on the generated reference as owned by the command line. It is not in .env.example.

Going to production ​

The example's own comments list what to change before you deploy it anywhere but your machine:

  1. In shared/auth-config.ts, make publicUrl your https origin plus /auth and remove cookies: { devMode: true }. The development cookie mode drops the __Host- and __Secure- prefixes and the Secure flag, which a browser needs over plain http, and is right only for http://localhost.
  2. With the development cookie mode off, EVO_AUTH_PROXY_SECRET becomes required on the Convex deployment too. Set it there to the value the app server has, or every auth route answers 503.
  3. Register a GitHub OAuth app whose callback URL is {publicUrl}/github/callback: GitHub OAuth app guide.

Hosting the built example ​

pnpm start in the example runs vite preview. That is not a production host. Vite answers OPTIONS itself on the dev server and on preview and adds Vary: Origin, whereas on a host without Vite in front, OPTIONS reaches the proxy and core answers 405 (there is no CORS).

A real host is a Node server that calls the fetch export of dist/server/server.js, with:

  • VITE_CONVEX_SITE_URL, EVO_AUTH_PUBLIC_KEYS and EVO_AUTH_PROXY_SECRET in process.env, and
  • the socket address passed for each request, since the proxy recipe reads it with getRequestIP().

VITE_CONVEX_URL is not read at run time. It is fixed into the browser bundle when you build.

Behaviour worth knowing ​

  • A missing variable gives Start's generic 500, with no Cache-Control or Vary, because the module fails before the middleware runs. The log names the variable.
  • Start sends /AUTH/... to the proxy case-insensitively. The proxy answers 404 with the page headers. Start answers //auth/... with its own 308, built from the Host header.
  • An app route on an exact path under basePath, or a longer prefix, takes precedence over the proxy without an error. Keep your own routes off {basePath}.
